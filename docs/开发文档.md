版本：0.1｜状态：框架搭建前的需求与设计基线｜日期：2026-09-25

本文将原始需求转为可实现、可验收的 Android 应用规格。本轮交付文档，不代表应用、模型或性能已经实现或验证。

配套文档：[上游参考与复用边界](./上游参考与复用边界.md)、[翻译配置与上游对照](./翻译配置与上游对照.md)。原始需求保存在 [初始提示词](./初始提示词.md)。

## 1. 产品范围与设计约定

目标：在手机上授权本地目录，发现漫画、管理书架、按漫画或章节翻译，并在阅读器中无损叠加译文；支持图片目录、CBZ、ZIP、PDF。

交互借鉴 EhViewer 的图库及下载分类布局、Mihon 的漫画详情及阅读器；翻译借鉴 manga-translator-android 的检测、OCR、LLM、气泡绘制流程。三者不能简单拼装：本应用需要统一的数据身份、存储适配、索引和任务系统。

### 1.1 需求的约束级别

| 标记 | 含义 |
|---|---|
| 用户要求 | 原始需求明确指定，实现不得静默删减 |
| 设计基线 | 为消除歧义选择的可调整默认值；框架先按此设计，并非用户已经确认 |
| 待验证 | 必须通过源码、模型资产或设备实验验证，不能视为已支持 |

下文未另标注的新增默认值均为设计基线。与用户要求冲突时，以用户要求为准。

### 1.2 本版范围

- 本地图库、两套路径表、单/多章节、增量索引、40 项显示批次、XML 元数据搜索。
- 书架、分类、分类文风、漫画级译名字典、阅读进度。
- Mihon 风格翻页及条漫阅读；原图与译文遮罩切换；当前页、章节、多章节翻译。
- 持久化翻译/导出队列、失败恢复、配置管理、备份恢复。
- 不默认引入在线漫画源、帐号、云同步、爬虫或下载站点；书架是收藏引用，不复制漫画原文件。
- “覆盖上游全部设置”采用逐项映射：翻译参数保留；图库/阅读参数映射到本应用对应页面；跨应用屏幕捕获功能单独列为扩展，不用空开关冒充可用功能。

### 1.3 关键歧义的默认解释

| 问题 | 本文采用的设计基线 |
|---|---|
| 单章节的“父文件夹名” | 指图片文件的直接父目录名。例如 `作品/001.jpg` → 漫画“作品”，内含同名章节；不取“作品”的上一级目录 |
| 归档单章节 | 每个 CBZ/ZIP/PDF 各自是一张漫画卡片，共 1 章，标题为去扩展名后的文件名 |
| 未勾选子目录 | 检测根目录自身及直接子级的漫画候选；允许检查候选内部的章节/图片，不继续深入寻找更远的漫画 |
| “首字母排序” | 默认文件名自然升序、不区分大小写，数字按数值比较；可切换严格字典序。封面固定按升序选取，不随详情列表倒序改变 |
| “上拉刷新” | 顶部下拉刷新 + 显式刷新按钮；向上滑到底部仅追加 40 项，不因分页重扫。若用户确指底部上拉刷新，再调整手势，不改变扫描接口 |
| 简介显示 XML | 详情默认展示可滚动的 XML 原文；卡片显示压缩的文本摘要；不只显示解析后的 Summary 而丢掉原文 |
| 一个漫画的分类 | 首版单分类，内置“未分类”；这样“跟随类别”的文风唯一。以后可扩展多标签，但需另设主文风分类 |
| 悬浮窗 | 阅读器内部可拖动控制条 + 与页面同坐标的遮罩层。核心阅读不依赖系统悬浮窗权限或屏幕截图 |
| 首启与后续启动 | 尚未完成路径配置 → 配置页；完成后的冷启动 → 书架；首次点下一步 → 图库 |

## 2. 术语和内容模型

| 对象 | 定义 |
|---|---|
| 图库源 Source | 用户授权的一条目录配置，含来源种类、树 URI、递归开关、单/多章节解释及顺序 |
| 漫画 Manga | 图库卡片与书架引用的对象；拥有至少一个章节。发现阶段允许章节总数暂未知 |
| 章节 Chapter | 一组有序页面；物理形式为叶子图片目录、归档文件或 PDF |
| 页面 Page | 图片文件、归档中的图片条目或 PDF 页；不要求事先解压或渲染全本 |
| 书架项 | 指向 Manga 的收藏关系、分类及加入时间，与源文件相互独立 |
| 译文产物 | 页面译文、气泡区域、轮廓、来源指纹和配置版本；保存在应用私有数据目录，可导出 |
| 索引缓存 | 可重建的目录/漫画/章节元数据和搜索索引。书架、进度、译名、人工修订不属于可随意清理的缓存 |

命名规则：文件夹/文件名作为稳定的默认展示名称；XML 的 Series、Title、AlternateSeries 作为元数据和搜索别名，不据此合并同名目录。作者未知显示“未知”，简介缺失显示“无简介”。

## 3. 导航与通用交互

```text
首次启动 → 设置/图库路径 → 下一步 → 图库 → 漫画详情 → 阅读器
后续启动 → 书架
主菜单：图库 / 书架 / 翻译队列 / 导出队列 / 设置
详情设置：翻译设置 / 译名管理 / 导出
书架右侧栏：全部 / 未分类 / 自建分类 / 管理分类
```

通用约定：触控目标不小于 48dp；图标有无障碍名称和长按提示；支持系统返回、字体缩放、深浅色和横竖屏。列表使用稳定 ID，恢复滚动位置。网络和磁盘操作不能阻塞主线程。

编辑弹窗统一使用“取消/保存”，有“应用”按钮的文风弹窗按其专用约定。非法输入就地提示并禁用保存，不悄悄改成默认值。取消不修改已保存数据。危险的源文件删除不放入本版普通操作。

DataStore 独立保存 `onboardingCompleted`，默认 false，首次成功点击下一步后置 true。后续删除所有路径或失去授权不清除此标记，冷启动仍进入书架并显示配置路径入口；“重新查看引导”只打开引导，不抹掉收藏数据。系统恢复当前 Activity 状态时可恢复原页面，冷启动默认书架规则不阻止正常的页面状态恢复。

每页具备加载、空、局部错误、可用数据并存的状态；单个文件损坏不能阻断整个库。错误显示可操作原因，如“目录授权失效—重新授权”“PDF 加密—暂不支持”“模型文件缺失—查看配置”。

## 4. 图库路径配置页

此页既是首次引导，也是设置中的同一个页面，不维护两份逻辑。路径表有固定表头与独立竖向滚动区域；手机窄屏可将行内路径折成两行，但保留四列。底部操作条固定，键盘弹出时保持保存按钮可达。

### 4.1 一张路径表（2026-09-25 合并）

原设计是两张表（图库路径 / CBZ-ZIP-PDF 导入），各自只解释自己那一类内容。真机验证发现
两张表在真实库里必然重叠（Tachiyomi 的 `/Tachiyomi/local` 里"章节是文件夹"与"章节是压缩包"
的作品混在同一层），而用户要为一棵树加两遍配置；更糟的是 `StableId.sourceId` 不含种类、
`library_sources` 主键就是它，同一目录加进第二张表会**覆盖**第一张表那一行。因此合并成**一张表**：
一次扫描同时识别图片章节（叶子图片目录）与归档章节（直接的 CBZ/ZIP/PDF），见 §5.1。

| 表 | 读取对象 | 说明 |
|---|---|---|
| 图库路径列表 | 图片目录 + CBZ/ZIP/PDF | 一次遍历同时产出两种章节；来源的“种类”降级为身份与徽标 |

“导入”默认是建立索引引用；只在随机访问能力不足时建立受限临时副本，不复制整个库。

| 控件 | 类型与默认 | 操作与保存 | 禁用/异常 |
|---|---|---|---|
| 表头 `+` | 图标按钮 | 打开系统目录选择器，返回后立即加入并扫描（唯一入口） | 取消选择不新增；同一目录不重复加入 |
| 当前路径 | 只读可复制文本框，初始空 | 显示提供方名称与可读路径；“重新选择”重新打开系统选择器 | 不允许手工输入路径伪造授权；无法解析真实路径时显示目录名及 URI |
| 路径列 | 点击行打开编辑；前置拖动手柄属于本列 | 改名或重新选择目录；改动即保存 | 完全重复的配置不允许新增 |
| 删除列 `×` | 图标按钮 | 移除索引来源，提供短时撤销；不删源文件/书架/译文 | 源正在扫描时取消该源任务；授权在所有引用释放后再释放 |
| 子目录列 | 复选框，默认勾选 | 勾选递归发现漫画；改动即保存并重新协调该源索引 | 不改变其余源 |
| 类型列 | **下拉选择**：多章节/单章节，默认多章节；选项由 `LayoutMode` 枚举生成（用户已预告将来加「混合」，见 §5.1） | 选中即保存并重识别该源 | 切换不静默合并既有进度；按稳定章节身份迁移 |
| 拖动排序 | 长按手柄上下拖动；另提供上移/下移辅助操作 | 松手立即持久化 | — |
| 路径状态 | 可用/检查中/失效/部分失败 | 点击失败状态查看原因、重试或授权 | 失效不视为该目录所有漫画被删除 |
| 强制重新扫描索引 | 页底按钮 | 已保存配置全部重建扫描；显示状态和取消按钮 | 无保存路径时禁用；重建不会删除用户数据 |
| 下一步 | 首次引导页底按钮 | 至少一个保存且可读的路径即可进入图库并异步扫描 | 不等待扫描完成；未保存编辑区提示保存或放弃 |
| 完成 | 普通设置入口替代下一步 | 返回原页面；后台扫描继续 | 删空所有路径后仍可保存，书架失效条目仍保留 |

路径行只读态显示四列；点子目录复选框或**类型下拉**即改动即保存（没有行内“保存/取消”二次确认）；点路径列打开改名/重新选择目录的弹窗。拖动排序同样即时持久化。首个新增目录的规则相同：选完目录立即加入并扫描。

根路径重叠：父子授权可共存；相同物理对象优先由最具体的授权目录解释，其次按来源排序。界面在保存时提示重叠及规则。**只有一张来源表**，因此不再有“两张表指向同一目录”的规则；同一个目录的图片章节与归档章节可以是同一部漫画的章节（并集，见 §5.1）。

Android SAF 的树 URI 是授权句柄，不是文件系统绝对路径；必须持久保存授权。Android 11+ 的系统选择器对存储根、Download 根及 Android/data、Android/obb 有限制，示例 `download` 是逻辑根；无法选中时引导选其下可授权目录。[Android 官方说明](https://developer.android.com/training/data-storage/shared/documents-files)

## 5. 扫描与分类的精确定义

### 5.1 图片目录识别

定义 `leafChapter(d)`：d 的直接子项中至少有一张支持的图片，并且没有子文件夹，**也没有 CBZ/ZIP/PDF**。XML、文本等普通文件不影响判断。为忠实遵循用户要求，隐藏子目录也算子目录；可另设忽略目录规则，但默认不擅自忽略。图片与子文件夹混放的目录标为“不符合叶子章节结构”，不静默遗漏，也不自动当章节。含归档文件的目录不是叶子：Tachiyomi 本地库里“章节就是压缩包”的漫画文件夹正是 `cover.jpg` + `第1话.zip` 这种形态，它是**一部漫画**（章节是那些压缩包）；若把它算成图片单章节，它的**父目录**会被误判成漫画并跳过其余子文件夹（真机 `/Tachiyomi/local` 实测：51 个子文件夹只扫出 1 张卡片）。

**两种解释共用一次遍历**（2026-09-25 用户确认并已落地）：一个目录的直接章节 = 「它直接含的 CBZ/ZIP/PDF」∪「它直接子目录里的叶子图片目录」，有章节它就是一部漫画。来源的“种类”因此不再决定扫描行为，只用于卡片身份；界面只剩一张路径表，“同一个目录要在两张表各加一遍”这件事不再需要（见 §4.1）。

“有一张图片”允许在确认存在性后停止图片内容探测；“没有子目录”通常必须消费完该目录的子项枚举，或者使用提供方可信的目录查询。不能因先看到图片就断言没有子目录。轻量扫描读取名称/类型等元数据，不解码所有图片。

| 来源模式 | 漫画判定 | 章节判定 | 根自身 |
|---|---|---|---|
| 单章节 | 每个 `leafChapter(d)` 为一本漫画；每个直接归档文件各为一本漫画 | 唯一章节就是 d（归档则是该文件自身） | 根是叶子图片目录则导入根自身 |
| 多章节 | d 至少有一个直接章节：直接的 CBZ/ZIP/PDF，或满足 `leafChapter` 的直接子目录 | 归档章节 = 直接文件（标题取去扩展名的文件名）；图片章节 = 叶子图片目录（标题取目录名） | 根存在直接章节则根本身是漫画 |
| 多章节但根本身是叶子图片目录 | 作为根特例，生成共 1 章漫画 | 根自身 | 用于用户选中单章节本体；不把任意深层叶子一律误认成独立多章节漫画 |
| 混合（预告，未实现） | 同一层里"叶子图片目录"各自成为一本共 1 章的漫画，容器目录继续按多章节判定 | 同左 | 用于"一个目录里既有单行本又有整套"的库（如 Tachiyomi 本地库） |

**混合模式的取舍**（写下来避免以后重新讨论）：它要求**在候选目录里检查完所有子目录**，
不能"找到第一个章节就跳过其余"，因此每部作品的成本从 ~1 次探测变成 ~N 次；用户此前
明确要求保性能、不接受这个代价，所以当时没有实现。真机 `/Tachiyomi/local` 用现在的多章节
规则已经能扫全（51 部），混合模式主要解决"授权根的直接子目录里既有单行本又有整套"这种
更混乱的布局。

递归单章节：深度优先/广度优先均可，但应按源轮转，避免一个巨大源饿死其他源。遍历直到找到叶子图片目录并发出漫画。

递归多章节：先检查候选目录是否有直接章节（**直接归档优先，零额外 IO**）；一旦存在即可发出漫画卡片，章节枚举可以稍后继续。用户明确要求“找到一个章节就跳过该目录其余子项”以换取性能，因此不再深入已判定为漫画的目录找更深的作品（开发文档 5.3 第 12 行据此调整）。

未递归：只将根自身及根的直接子目录作为漫画候选；为识别多章节候选，可读取候选的直接章节层和章节的直接图片层。这种必要的结构检查不等于向更深处发现漫画。

漫画发现与章节同步分开：发现第一章足以创建卡片；准确章节数和后续新增章节必须枚举所有直接章节候选。界面先显示“已发现 ≥1 章/章节待更新”，不得把探测到一章伪报成完整的一章。

结构判定只依据目录层级，不能从“作者/卷/话”等名称可靠推断语义。因此多章节模式取直接包含叶子章节的目录，不向更高祖先自动折叠；卷下还有话时按卷拆成卡片。若希望把全部卷合成一本，需要未来显式层级配置，不在本规则中猜测。用户可通过更换来源模式、选择更具体的授权根解决单篇集合误分组。

### 5.2 归档和 PDF

两种解释共用一次遍历之后，归档章节与图片章节由**同一次扫描**产出（§5.1），不再要求用户把同一个目录加两遍；`sourceKind` 只作为来源身份保留，卡片内容由章节种类表达（`hasArchiveChapters`）。

- 单章节：每个直接归档文件生成一本共 1 章漫画；章节标题为文件名去扩展名。
- 多章节：包含至少一个直接 CBZ/ZIP/PDF 文件的目录是一部漫画；章节是那些直接文件；同一目录里的叶子图片目录也可以是它的章节（两者并集）。
- 未递归时仍检测根自身及直接子目录；递归时继续向下遍历子目录。
- ZIP/CBZ 只读取中央目录及必要条目，允许压缩包内部有包裹目录，图片按归一化相对路径自然排序；内部的 ZIP 不递归解包，一个外部归档始终一章。
- PDF 每个页面是一页漫画，按 PDF 原生页序，不按渲染图片名排序；读取页数、按需渲染首页与阅读页。目录没有图片不影响 PDF 的章节资格。
- 扩展名比较不区分大小写；打开时校验格式。空归档、加密/损坏归档、无图归档、加密/损坏 PDF 留在诊断列表，不阻断其他作品。密码输入作为后续扩展，首版明确标注暂不支持。
- 首版图片格式：JPEG、PNG、WebP、GIF（静态首帧）；AVIF 等格式按设备解码能力暴露。检测到不支持图片时显示具体原因，不声称可以翻译。

### 5.3 结构验收样例

| 授权与配置 | 文件结构 | 预期 |
|---|---|---|
| `download`，递归多章图片 | `pixiv/网球王子/第一章/001.jpg` | 漫画“网球王子”，章节“第一章”；不是 pixiv |

## 6. 索引、更新与大图库性能

### 6.1 三阶段扫描

1. **发现**：枚举目录元数据，识别漫画/章，批量写数据库；不逐图解码，不提前生成全部页表。
2. **补全**：当前可见卡片优先补封面、首章 XML；后台低优先级补全部首章元数据，保证未显示卡片也可按简介搜索。

   > 实现偏离（用户口径，2026-09-28 已在真机确认后修正）：**封面不在扫描期取**。
   > 扫描只写路径；封面由图库/书架/搜索结果**滚动到可见时**懒加载（一次一批 30 项、
   > 并发 2、队列上限 200），取过一次就写 `coverProbedAt` 不再取；只有详情页的
   > 「更新章节」强制重取。原因：扫描期取封面要为每部漫画多开一次章节目录（拖慢扫描），
   > 而且每轮只补 120 条，万级图库永远追不上——真机 5408 部里只有 742 部有封面。
3. **深入**：打开详情/更新章节时枚举该漫画章节；进入章节或翻译时建立该章完整页面清单。后台变化扫描也会对已有漫画枚举直接章节名称，发现新增/移除。

发现不足 40 项时按最长 250ms 批次延迟提交；40 项是显示增长单位，不是“必须凑够才可见”的门槛。封面失败用占位图，卡片不等封面完成。

### 6.2 可靠的变化扫描

不能只看 `mtime > lastScanTime`，也不能因父目录时间没变就跳过整个树。每次刷新对配置范围内所有容器重新枚举直接子项，比较稳定文档 ID、名称、种类的集合，发现旧时间戳的新目录、新章节与删除。目录摘要只是比较已枚举结果的工具，不是跳过枚举的可靠凭证。

维护 `ScanRun(generation, sourceId, sourceConfigRevision, status)` 及 `DirectorySnapshot`。每次完整列举目录成功后，事务性 upsert 成员并提交该目录新快照；只在覆盖完整、没有权限/IO 错误且配置版本未变的目录中判定删除。源扫描取消/失败不能把未访问条目标为删除。全源重建期间旧索引继续可读，逐目录原子替换。

时间/大小用于决定封面和普通文件是否值得重读，但不用于判定目录/章节是否存在。XML 通常很小：元数据更新阶段重新读取并计算内容摘要，以发现同时间同长度的描述变化。大图片的同大小同时间原地替换不能靠轻量目录扫描保证发现；翻译/导出前计算源内容 SHA-256，强制深检可逐页重算。UI 区分“目录与章节更新完成”和“全部文件内容校验完成”。

SAF 提供方返回的文档 ID 在同一提供方内优先用于对象识别；不能把 URI 字符串拼接当稳定路径。跨提供方搬迁或删除重建可能失去身份，默认产生新来源，支持“重新关联失效漫画”；不自动仅凭标题合并进度。图片内容哈希属于翻译产物绑定，不要求首次索引整库哈希。

### 6.3 触发规则与并发

| 动作 | 行为 |
|---|---|
| 普通冷启动 | 先读本地缓存，快速校验源授权；不强制全库扫描 |
| 首次下一步/保存新路径 | 扫描新增或改变的源 |
| 打开搜索 | 当次搜索会话触发一次全源变化扫描并补全首章 XML；立即查询已有缓存 |
| 输入关键字 | 300ms 防抖查询数据库，不为每个字符启动扫描；扫描中只更新结果 |
| 搜索显式刷新/图库刷新 | 请求全源变化扫描；正在扫描则合并请求，必要时结束后补一轮 |
| 更新章节 | 只扫描当前漫画结构及章节元数据，保留阅读与翻译数据 |
| 强制重新扫描索引 | 不用旧的结构判断缓存重建可派生索引；保留稳定 ID、收藏、进度、人工编辑；可选深度内容校验 |
| 权限恢复/外部文件变动通知 | 将相关源标脏并请求扫描；系统事件只是加速提示，不是唯一依据 |

每源最多一个结构扫描任务；全库调度按源轮转。默认同时枚举目录 2 个、封面解码 2 个，作为起点经设备测试再调优。用户阅读优先于后台缩略图和批量翻译。

### 6.4 40 项分页与搜索

- UI 初始最多显示 40 个已发现条目；到列表末端加载下一批 40。已发现只有 17 个就先显示 17，扫描继续时可补至当前 40 项额度。
- 后台索引不随用户停止滚动而停止，否则全库搜索无法完整。数据库储存全部轻量索引，UI 只观察当前窗口，不把万级数据一次送入 Compose。
- 采用会话顺序表与 keyset 分页，避免扫描增删导致 OFFSET 翻页重复/丢失：新会话先按当前有效源顺序、所选排序键、mangaId 生成递增 rank；扫描中新发现且符合查询的 ID 按提交批次追加 rank。按 `(sessionId, rank)` 分页，当前显示额度有空位时立即补入，满额则留待下一次滚动追加。不会为了稳定排序而阻止首批不足 40 项继续补齐；当前可见元数据可原位更新。
- 扫描中显示“正在发现，完成后可按名称重排”；“有 N 项更新”用于提示新条目及排序字段变化。用户点重排/刷新、新搜索或更改排序时建立新会话，才按完整当前排序重新排列；已有会话不把新条目插到滚动锚点前。被删除/不再匹配的 ID 从会话移除，保留其他 rank 并补足额度。
- 有效源顺序取去重归属后的 `effectiveSourceId` 对应源顺序；同一表先按最具体授权目录归属、再用配置 order 决定（只有一张来源表，不再有跨表次序）。调整路径顺序触发新会话，不改当前会话已经分配的 rank。
- 搜索同样按 40 项分页。范围含漫画名、首章及已索引章节名、XML 原文文本/属性、Series/Title/AlternateSeries、作者、标签、Summary。首版至少保证漫画名与首章 XML 全库可检索。
- 查询规范：Unicode 规范化、不区分大小写、多词 AND；保存原文不变。P1 采用规范化文本列+2-gram 侧表筛候选，再以规范化子串校验；单字符查询走文本列子串匹配。gram 按 Unicode code point 生成，不能拆代理对；FTS 作为未来优化，不能只用默认英文 tokenizer 宣称支持中文。
- 搜索显示“正在更新索引/简介索引中，结果可能不全”；完成后显示匹配总数。不把扫描尚未结束时的零结果显示为最终“没有漫画”。

漫画级搜索投影每漫画一条 `MangaSearchDocument`，包含名称、别名和按第 7 节选出的首章/回退 XML 文本，记录 metadataOwnerId、fingerprint 与 revision；章节自己的原始 XML 仍按章节独立保存。首章变化、XML 内容变化或解析状态变化时同事务更新搜索投影和 gram 索引。后台补全扫描不以“已显示卡片”为前提。可对超过索引体积预算的极大 XML 不建 gram，记录 `requiresTextScan=true` 并并入文本匹配查询，不能因优化而漏掉可读取文本。归档内 XML 同样先受大小上限保护。

### 6.5 缓存与数据保留

缩略图、临时归档副本、PDF 栅格化页为有大小上限的 LRU 缓存；翻译 JSON、人工修改、译名字典、进度为持久数据。清缓存界面分别显示体积与影响，不把译文归入一键清缓存。

临时副本以源文档 ID + 内容版本绑定；在复制完成并校验前不让阅读器使用。空间不足可取消，保留可读原源和错误条。跨会话失效副本可清理，活跃任务持有引用的副本不能被淘汰。

## 7. ComicInfo 与封面

读取名称不区分大小写，但不把任意 XML 都当 ComicInfo。支持标准字段以及 EhViewer 的 AlternateSeries/Characters/Teams/CommunityRating，Mihon 的命名空间扩展字段；未知字段保留原文并可搜索，不因为 schema 中没有而丢弃。

### 7.1 元数据来源优先级

1. 单章：章节目录的 ComicInfo.xml；归档则查归档根，允许唯一包裹目录内的 ComicInfo.xml。
2. 多章：按固定章节自然升序的第一章 XML，严格符合用户“第一章做简介”的要求。
3. 第一章无 XML：允许回退漫画目录顶层 ComicInfo.xml，以兼容 Mihon 本地源；明确展示来源。没有则“无简介”，不静默选任意后章。
4. PDF：优先同目录同基名 sidecar，如 `01.ComicInfo.xml`；章节专属目录可读其中 ComicInfo.xml。PDF 原生标题/作者仅补缺字段，不伪造 XML。

不照搬 Mihon 把 XML 复制回源目录或创建 `.noxml` 的写入逻辑：本应用默认只读源，负缓存必须在下一次有效扫描重验。

**读取实现约束（真机教训，2026-09-28）**：打开目录读 `ComicInfo.xml` **必须**经过统一的树入口（`TreeAccess.openAt` / `openInputStream`），不能直接用 `DocumentsContract.buildChildDocumentsUriUsingTree` 拼 SAF URI。在“全部文件访问”模式下 documentId 是绝对路径而 ExternalStorageProvider 要的是 `primary:…`，拼出来的 URI 查不到任何子项，结果是每一部漫画都被判成“没有 XML”——简介与作者永远是空。

XML 按纯文本展示、可展开/复制、显示来源章节和更新时间；格式错误展示原文及解析失败提示，标题与阅读继续工作。解析关闭外部实体及网络访问，设置 2MiB 默认上限；超限提供查看说明而不在列表解析巨文档。搜索覆盖可读取部分时明确标记。

**加固的取舍（真机教训，2026-09-28）**：Android 的解析器（libcore 的 Harmony 实现）**不认** OWASP 那套按 JDK Xerces 写的 XXE 加固属性，并把拒绝延迟到 `newDocumentBuilder()`：`ParserConfigurationException: This parser does not support specification "Unknown" version "0.0"`。因此加固是“标准配置试一次，被拒就退回最小配置”，而 XXE 的**真正保证**改成与实现无关的两条：解析前按原文拒绝 `<!DOCTYPE`（没有 DTD 就没有实体声明），以及 2 MiB 上限。

### 7.1A 两侧上游的字段语义不能等同

同名字段的业务含义不同，取“作者”必须看是哪一侧写的（考察 `.research/mihon` 的 `Downloader.createComicInfoFile` 与 `.research/EhViewer` 的 `spider/ComicInfo.kt`）：

| 字段 | Mihon / Tachiyomi | EhViewer |
|---|---|---|
| `Summary` | 漫画简介 | **不写** |
| `Writer` | 作者 | **社团 / 同人圈** |
| `Penciller` | 画师 | **作者 / 画师** |
| `AlternateSeries` | 不写 | 日文原名 |
| `Genre` | 分类 | 其它标签，女性/男性向带 `f:`/`m:` 前缀 |
| `Characters` / `Teams` | 不写 | 角色 / 原作 |
| `PageCount` / `LanguageISO` / `CommunityRating` | 不写 | 页数 / 语言 / 评分 |
| `PublishingStatusTachiyomi` / `Categories` / `SourceMihon` | 写 | 不写 |

判定按**字段集合**（两侧互斥的那几个字段），不按命名空间前缀——前缀是写法而不是来源。判不出来时按 Mihon 语义。作者取 `Writer`（Mihon）或 `Penciller`（EhViewer），另一侧字段作回退；EhViewer 的社团单独显示。EhViewer 没有 `Summary`，简介按其可用字段组织成带标签的行（别名/作者/社团/分类/角色/原作/信息/来源/名称），判不出来源的第三方 XML 才回退到压缩原文。

### 7.2 封面优先级

用户手动指定封面（可选增强）→ 漫画目录约定的 `cover.*` → 首章 XML 的有效 FrontCover 页标记 → 第一章第一页 → 占位图。未添加手动封面功能时第一项自然跳过。第一章空或损坏则按后续第一个可读章回退封面，显示异常；简介仍不因此换成后章 XML。

封面最早也要拿到正确排序下的第一张图片，不能使用目录枚举碰巧返回的第一张。读取目录名称元数据与解码所有图片是不同成本。改变章节顺序显示不会更换默认封面；源删除、替换首章或封面摘要变化才刷新。

**更新封面时必须同时更新简介**（用户要求，2026-09-28）：封面与简介读的是同一批目录，分开走会变成"卡片有封面、简介一直是空的"（简介只由扫描期补全负责，每来源每轮 120 条）。图库、书架、详情页三处落库统一走 `CoverMetadataWriter`；简介已探过的作品由 `metadataProbedAt` 守卫，滚动不会重复枚举目录，只有详情页「更新章节」强制重读。

### 8.2 书架与分类

书架默认所有收藏，布局和搜索可复用图库。移出书架只删收藏关系，漫画仍在图库、原文件仍在。源暂不可用时保留书架卡片，标灰并提供重新授权/重新关联，已有本地译文也保留。

| 控件 | 类型/默认 | 行为 |
|---|---|---|
| 右侧分类栏 | 右上分类按钮打开，不要求边缘手势 | 全部/未分类/自建分类，显示数量 |
| 新分类 `+` | 弹窗 | 名称必填 1–40 字符；同名禁止；文风默认“跟随全局默认” |
| 分类长按 | 菜单 | 重命名与文风、上移、下移、删除 |
| 分类编辑 | 名称框 + 文风多行框 + 跟随默认开关 | 保存后统一更新分类名称与文风版本；不会自动重译 |
| 删除分类 | 确认操作 | 收藏移到未分类；保留漫画覆盖文风和字典；不移出书架 |
| 加入书架 | 分类单选弹窗，默认未分类 | 可就地新建分类；取消不加入 |
| 已在书架 | 按钮状态 | 点击可更换分类/移出书架；不重复建立收藏 |

分类文风解析：漫画独立文风 > 漫画指定“全局默认”或“跟随类别”的解析结果。跟随类别时，类别独立文风 > 全局文风 > 内置文风。未加入书架或在未分类时回退全局。修改分类不影响已经开始的任务快照。

## 9. 漫画详情与章节多选

标题位于上方；封面在信息区左上；右侧/下方显示漫画名、作者、来源、章节数和 XML 简介。窄屏自动换行，三主按钮不能被封面挤出屏幕。

| 控件 | 默认/选项 | 点击或状态变化 |
|---|---|---|
| 加入书架 | 未收藏 | 选分类后收藏；已收藏显示“已在书架” |
| 更新章节 | 可用 | 单漫画扫描；扫描中显示转圈并合并重复操作 |
| 阅读 | 有进度显示“继续阅读” | 恢复章节+页+条漫页内比例；否则第一章第一页；无可读章禁用 |
| 右上翻译 | 图标 | 弹出范围/模式确认；默认全部未翻译章节；必须显示章数及已知页数再提交 |
| 右上筛选与排序 | 图标 | 底部面板，见下表 |
| 右上设置 | 图标 | 翻译设置、译名管理、导出；阅读偏好也可从阅读器打开 |
| XML 简介 | 默认可折叠区域 | 显示 XML 原文，复制，展开；无则无简介 |
| 章节总数 | 单章模式固定“共 1 章” | 多章未完成枚举显示“已发现 N 章，更新中”，完成后准确总数；有已读时附“· 已读 N” |
| 章节行 | 标题、已读/书签、页数或未知、翻译状态 | 单击阅读（多选态下改选择）；**长按选中**；**再长按已选中行拖动排序**；见 §9.1 |
| 章节多选 | 选中数 + 整行容器色 | 全选当前筛选结果/反选/清空；全选作用数据库匹配集合，不限当前加载行，并明确总数 |
| 多选操作条 | 标已读/标未读（翻译/导出待阶段 2） | 操作固定章节 ID 集合，刷新后不以行号错选；已删除项提示跳过 |

筛选面板：阅读状态（全部/未读/已读）、书签（全部/有/无）、翻译状态（全部/未翻译/部分/完成/失败/待更新）、来源类型（图片目录/CBZ/ZIP/PDF，多选）。不同组 AND，同组 OR。章排序（文件名自然序/XML 章节号/发现时间）、升降序；无章号排在有章号后，再按自然名+ID。默认自然升序。面板有“重置/应用”，记住每漫画设置，不改变实际阅读页序或首章元数据规则。

### 9.1 章节顺序（已实现，2026-09-28）
**两种"顺序"必须各有一列**，合成一个字段必然坏掉一边：

- `chapters.sortKey`（自然序，**永远**）——回答"哪一章是第一章"，供封面（§7.2）与简介（§7.1 第 2 条）取**自然序第一章**。用户手动拖过章节也不能换一章；
- `chapters.position`（显示顺序）——详情页章节列表唯一的排序依据；排序抽屉整表重排、手动拖动、扫描发现新章节时的插入都写它。

**排序抽屉**：表头的排序图标不变，点击从屏幕下方弹出面板，三项——首字母排序（纯字典序，不认数字大小）、按修改时间排序（目录/归档文件的 mtime）、按自然数字排序（1 < 2 < 10 < 100）。**同一项点一次正向、再点一次逆向**；每一项都会整表重排并落库（用户已确认：这是把拖乱的列表整理回来的唯一手段）。手动拖过之后面板显示"当前：手动"，此时点任意一项都会重排。

**新探到的章节**按**用户已保存的排序方式插入**到对应位置，已有章节的相对顺序一个都不动（用户口径："依然是根据用户勾选的方式进行插入，不改变用户的操作"）。用户从未选过排序方式时退回最初口径：追加到末尾，同一批之间按首字母。定位规则是"当前顺序里最后一个不比它大的项之后"，列表本来有序时与整表重排等价。

**长按与拖动**（参考 Mihon）：长按章节 → 选中（整行加容器色）；**再次长按已选中的章节** → 进入拖动，多选态下也能拖，但一次只拖这一章，其余选中项保持不动。多选顶栏为 `✕` + 选中数量 + 全选 / 反选；多选态下单击 = 改选择，非多选态单击 = 打开阅读器。返回键先退出多选。

**按章的已读标记**存在独立表 `chapter_read_state`（开发文档 15.3「用户状态与索引分表」），**不是** `reading_progress.read`——那张表一部漫画只有一行，"已读"只描述当前那一章。没有行的章节 = 未读（500 章里只标 3 章不该写 497 行）。

**简介**默认折叠为 3 行，超出时给「显示更多 / 收起」；短简介不显示按钮（`hasVisualOverflow` 才给）。

阅读完成定义：翻页模式到最后一页且停留达到默认 1 秒；条漫最后一页末尾进入可视区达到 1 秒。手工标未读重置已读状态，可保留最后位置；阅读按钮允许“从头阅读”。

## 10. 漫画级翻译设置与译名字典

### 10.1 控件及模式组合

顶层“跟随全局翻译设置”默认开。关闭后复制当前有效设置作为漫画覆盖；可随时恢复跟随。文风和译名字典独立于这个开关，不因恢复全局而丢失。

**已实现的部分（阶段 2，2026-09-28）**——都是先于模型落地、且不依赖模型就能生效的：

| 入口（详情页右上角 ⋮） | 现状 |
|---|---|
| 全部翻译 / 多选底栏「翻译所选」 | **真的入队**：写 `chapter_translation` 待翻译记录，侧栏「翻译队列（N）」角标随之变化；章节行副标题显示「待翻译 / 翻译中 / 已翻译 N 段 / 翻译失败」 |
| 多选底栏「清除翻译」 | **真的删译文**：清掉该章译文条数与完成时间，并把状态退回「待翻译」（用户口径：都没译文了不得待翻译） |
| 译名管理 | **真的落库**：按「漫画 × 目标语言」的键值字典，增 / 改 / 删；人工录入的条目不会被将来的自动抽取覆盖（TR09） |
| 文风设置 | **真的生效**：覆盖关系 漫画 → 分类 → 全局；页面上同时给出各层现值与**最终生效的是哪一层** |
| 翻译语言 | **跟着每部漫画**：源语言 / 目标语言各是一个选择列表，**表尾有自定义输入框**（支持任意语言），源语言另有「自动识别」；留空 = 跟随全局默认 |
| 翻译设置 | **诚实的进度说明页**：列出已经能用的与 P3 才做的，不放还不能生效的输入框（开发文档 17） |

入队记录带**入队那一刻**的有效配置快照（语言、是否自动识别、文风），因此用户随后改设置不会让已排队的任务换一种翻法；队列按 `(chapterId, targetLanguage)` 存，同章翻成两种语言是两份独立任务。

**还没做（P3）**：模型资产（检测 / OCR / 主模型）的来源与校验和、任务调度与重试、主 AI 配置、页面与气泡的译文渲染。因此现在只排队、不会真的开始翻译——这一点在「翻译设置」页里如实写明。

| 控件 | 默认/类型 | 规则 |
|---|---|---|
| 全文速译 | 继承全局；全局默认关闭 | 开启后采用章节范围的 OCR 预处理和批量文本翻译。不是把整本原图一次上传 |
| 译名处理 | 继承全局；全局默认开启 | 开启自动提取并新增译名；关闭仍向翻译请求附带已有字典，所有模式一致 |
| 使用 VL 模型翻译整个气泡 | 继承全局；全局默认关闭 | 气泡截图直接交视觉模型；跳过该气泡 OCR；需视觉能力 |
| 全文与 VL 互斥 | 两个独立显示开关 | 用户打开其中一个时将另一个关闭并就地说明；不在后台悄悄切换已提交任务 |
| 设定翻译文风 | 进入专用弹窗 | 显示当前有效文风及来源：本漫画/分类/全局 |
| 语言设置 | 源语言、目标语言单选 | 默认日语→简体中文；与界面语言分离；本地 OCR 不支持的语言组合要求改 API OCR |
| 译名管理 | 进入当前漫画字典 | 按目标语言分区，跨章节共享；不建立未请求的全局字典 |

文风弹窗必须有多行文本框及三个按钮：“恢复默认”“跟随类别”“应用”。恢复默认设置草稿模式为 GLOBAL 并显示全局文风；跟随类别设置草稿模式为 CATEGORY 并显示类别解析结果；两个按钮都不直接落盘。手工编辑转 CUSTOM；应用保存模式与文本，关闭弹窗。取消/系统返回丢弃草稿。默认内置文风为“忠实原意，译文自然流畅，保持人物语气、称谓和前后文一致，不添加解释。”

### 10.2 译名字典编辑

| 控件 | 类型/默认 | 规则 |
|---|---|---|
| 目标语言 | 下拉，当前翻译目标 | 切换字典分区，不自动翻译已有条目 |
| 搜索 | 文本框 | 搜原词/译名 |
| `+` | 新增行 | 原词和译名必填；可加备注，标记手动来源 |
| 原词 → 译名 | 两个文本框 | 保存前去首尾空白；原词按 NFC 后精确去重，避免大小写归一化误并专名 |
| 删除 `×` | 行按钮 | 标记删除，保存后生效；可撤销 |
| 保存 | 页底按钮 | 事务提交、字典版本+1；冲突提示具体原词 |
| 导入/导出 | 菜单增强项 | UTF-8 JSON；先预览新/冲突项；默认保留人工词条 |
| 来源/冲突 | 手动/自动/待解决 | 自动新增不能覆盖同键旧值；冲突待用户选择 |

请求契约：STANDARD、FULL_TEXT、VL 的每一次翻译请求都获得漫画目标语言的字典快照。关闭译名处理时禁止提取步骤、忽略模型回传的新词并禁止写入；开启时串行合并新增，不覆盖人工词条。VL 上游路径需专门补充字典注入和结构化回传，不能假定原实现已满足。

本应用统一模型响应契约 v1：`items` 包含唯一请求 ID 与 `translation`；开启译名处理时响应还必须带 `glossary_used` 对象，值为本次识别的原词→译名，无新词用空对象。VL 开启译名处理时，各 item 还须带 `source_text`，用于记录视觉模型识别出的原文及审核新词。请求携带 `mode/sourceLanguage/targetLanguage/style/glossary/autoGlossary`；标准/全文 item 提供 OCR 文本，VL item 提供带 ID 的裁图。参考响应：

```json
{
  "items": [{"id": "p1-b1", "translation": "网球王子", "source_text": "テニスの王子様"}],
  "glossary_used": {"テニスの王子様": "网球王子"}
}
```

`source_text` 仅在 VL+自动译名时必需；普通路径已有 OCR 原文。自动译名关闭时不要求 glossary_used，即使返回也不写入；开启时缺失该对象、词条非字符串或出现无效键则属于结构错误，有限重试后本页失败。ID 校验、空译文约定同 11.1。不支持此结构的模型可换模型或修正配置，不悄悄退化成“不用字典/不新增”的成功结果；P0/P3 使用模拟响应与真实视觉模型共同验证六组合。

同漫画的自动译名合并串行化；任务开始保存基础字典版本，每批请求保存实际使用的快照版本，新批次可以用该任务新增词。用户在运行中修改字典不会偷偷影响已发请求；任务完成提示“字典已变化，可重译”，重新开始才采用用户新版本。

严格的上下文长度约束：默认每个请求应用整个字典；超出模型能力时显示“字典/文本超出上下文，需降低批次或调整字典”，不能静默截断。后续按相关词检索须作为显式配置，并改变可复现记录。

## 11. 翻译流水线与队列

### 11.1 页级流程

```text
展开章节页清单 → 固定内容身份及设置快照 → 检查已有结果
  标准：检测气泡/游离文字 → 本地或 API OCR → 文本+字典+文风 → LLM
  全文：所选章分段 OCR → [开启译名处理才做预提取] → 按预算批量 LLM
  VL：检测 → 气泡裁图+字典+文风 → 视觉 LLM
→ 校验 ID/结构 → 合并译名 → 原子保存页结果 → 更新进度 → 阅读器通知
```

全文速译按“章及受限页块”预处理，不把万页全部装入内存；跨章不拼图片。多页合并仅合并请求文本并生成请求级唯一 ID，拆回源页坐标。条漫跨页气泡作为专门的临时关联，不能写成跨页坐标污染普通页缓存。

无文字页标为“完成（无文字）”，不是失败。响应缺少/重复/多出气泡 ID、格式截断时不得错位配对译文；有限重试后保留错误供重试。空译文按协议表示隐藏该气泡，不能自动视为整页失败。

### 11.2 提交翻译弹窗

范围：当前页/当前章/选中章节/全部章节；详情默认“全部未翻译”，多选默认所选集合，阅读悬浮条默认当前页。显示有效模式、语言、文风来源、模型、章数/页数（未知时先枚举），以及将跳过的已有结果数量。

结果策略单选：“补全缺失”（默认）/“按当前设置重新翻译”。配置变化的旧结果保留并标“待更新”；补全不覆盖旧人工结果。重新翻译生成新版本，可切回旧版本；人工修订需要显式包含才能被新结果替换。

提交按钮“加入队列”；取消不发送请求。配置缺失时按钮改为“去配置”，保留选中范围。此弹窗是实际任务参数选择，不再追加无信息的重复确认。

### 11.3 队列状态与控件

持久状态：WAITING、PREPARING、RUNNING、PAUSING、PAUSED、WAITING_NETWORK、INTERRUPTED、SUCCEEDED、PARTIAL_FAILED、FAILED、CANCELLED。页子任务单独记录，重试只处理指定失败/缺失页。

| 控件 | 内容/默认 | 规则 |
|---|---|---|
| 状态筛选 | 全部/进行中/已完成/失败 | 默认进行中 |
| 任务卡片 | 漫画、章范围、模式、语言、已完成/总页、阶段、错误数 | 未知总数显示正在枚举；OCR 与翻译分阶段，不以 OCR 完成冒充翻译完成 |
| 总进度 | 完成页数/已确定总页数 | 部分失败显示成功/失败/跳过数量，不只报 100% 成功 |
| 暂停/继续 | 按状态显示 | 暂停不再发新请求，当前请求可完成落盘；继续从断点恢复 |
| 取消 | 运行态可用 | 取消请求并停止后续页，保留已完成结果；远端已接收的请求可能仍计费 |
| 重试 | 失败/中断可用 | 默认仅失败页；同页已有结果先校验 |
| 查看错误 | 有错误可用 | 具体到源/章/页及原因；提供定位和重试，不展示密钥 |
| 拖动排序 | 等待任务 | 只调整未开始任务优先级，不打断当前原子保存 |
| 清理已完成 | 菜单 | 只清队列记录，不删译文 |

默认一漫画任务执行，跨漫画可队列并发；网络并发、OCR 并发、图像解码并发分别限流。核心 UI 显示实际并发上限，设置大并发值不保证设备能运行同等数量。当前页手动翻译可插队，但同页同配置任务去重。

网络错误、超时、408/429/5xx 可按指数退避及 Retry-After 重试；认证/参数错误等待修正，不无限重试。失败重试次数定义为首次请求之外的次数，避免与上游混淆。离线本地阅读始终可用；依赖 API 的任务处于等待网络，不退化成假译文。

进程重启：恢复持久队列为 INTERRUPTED，默认由用户点继续后联网运行；利用页产物跳过已完成。与上游“冷启动清除活动任务描述”不同，这是本应用新增能力。任务宿主与界面生命周期解耦，用符合系统限制的前台执行服务及通知；不承诺无期限后台保活，具体 Android 版本限制在框架阶段做设备实验。

### 11.4 翻译产物与失效

持久产物包含：schemaVersion、mangaId/chapterId/pageId、源内容 SHA-256、原图宽高和方向、PDF 页/栅格化参数、mode、源/目标语言、prompt 版本、实际文风、字典快照版本、模型标识、气泡原文/译文/矩形/轮廓、手工修改标记、生成时间。

将“旧结果可以阅读”和“当前设置下可直接跳过翻译”分开。源内容变了，旧遮罩不得直接盖到新图；样式/字典变了，旧译文保留并提示待更新，用户决定何时重译。切换供应商本身不删除已有结果。只改字体/透明度/颜色可重绘，不请求 LLM。

写入采用临时文件+原子替换（应用私有文件系统），结果与数据库引用协调提交；孤儿文件可修复。译名更新与页完成状态一起保证可恢复，不能先把页标完成再丢失该页新词。

## 12. 阅读器与遮罩

以 Mihon 的分页/条漫交互为参考，用适配层接入同一个 Chapter/PageSource；不复制其在线源、下载、跟踪站点服务。核心设置如下。

| 控件/设置 | 选项与默认 | 行为 |
|---|---|---|
| 顶栏 | 返回、漫画/章名、更多 | 轻触中央显隐；返回保存进度 |
| 底栏 | 页码、滑块、上一章/下一章 | 拖动只预览目标，松手跳转；加载错误可重试 |
| 阅读方向 | 右→左（默认）/左→右/竖向分页 | 影响翻页与点按分区，不改变页 ID |
| 连续模式 | 关闭（默认）/连续竖向/条漫无缝 | 条漫保留页内比例进度和每页坐标 |
| 缩放 | 适合页面（分页默认）/适合宽度（条漫默认）/适合高度/原始比例 | 双击缩放、双指缩放；大图分块解码 |
| 加载原图 | 默认关；开启后按原始像素解码 | 关：超过「屏幕短边 × 4/3」的图按 2 的幂降采样（更省内存、翻页更稳）；开：一个像素都不减，代价是单页解码量回到原图大小（一页 3000×1700 约 20MB）。切换后当前页立刻按新策略重新解码 |
| 裁白边 | 关闭默认，开启时自动裁剪 | 原图与遮罩共用变换矩阵 |
| 屏幕方向 | 跟随系统/锁定竖屏/锁定横屏 | 旋转后恢复当前页及浮条位置 |
| 亮度/常亮 | 跟随系统/手动；阅读时常亮默认开 | 离开恢复系统值 |
| 音量键翻页 | 默认关，可反转 | 开启后尊重阅读方向 |
| 页切换动画 | 滑动/无；默认滑动 | 系统减少动画时适配 |
| 双页 | 后续能力验证项 | 未完成适配前不提供可用开关；需要两套页变换及封面单页规则 |

### 12.1 悬浮条

可拖动、吸附边缘、折叠，位置按屏幕方向记忆，避开系统安全区。不是单独遮住原画的另一张全屏截图。

| 控件 | 默认 | 行为 |
|---|---|---|
| 原图/遮罩切换 | 遮罩优先；无有效译文显示原图 | 只控制显示，不自动请求翻译；下一页沿用偏好 |
| 翻译当前页 | 当前页 | 展示模式摘要后提交；已在队列显示进度 |
| 章翻译 | 展开菜单 | 提交当前章，复用队列弹窗 |
| 遮罩透明度 | 100% | 预览即生效；0% 不改变存储译文 |
| 气泡编辑 | 有结果时可用 | 点气泡改译文、隐藏/新增区域、调整框；保存为人工版本 |
| 临时看原图 | 按住指定按钮 | 松手恢复切换前状态，不改变记忆偏好 |
| 错误/待更新 | 有错误时显示 | 查看原因、重试；无结果不绘空白覆盖层 |

遮罩使用源图坐标（带原始宽高、方向），绘制时与图片共用 `sourceToView` 变换，包含缩放、平移、裁边、旋转、双页及条漫偏移；触点用逆矩阵映回源坐标。PDF 结果绑定页号与固定规范化页面空间，不随设备显示 DPI 漂移。

绘制为原图+区域填色/轮廓+译文，不宣称实现生成式背景修复。文字排版复用可验证的气泡布局；透明度/背景取色失败时使用可读默认。页面回收时解绑观察者，异步结果通过 pageId 检查，不能把上一页结果盖在下一页上。

## 13. 导出与导出队列

从漫画设置、章节多选或阅读器进入同一导出配置；不要求先加入书架。

| 控件 | 选项/默认 | 规则 |
|---|---|---|
| 范围 | 当前页/当前章/选中章/整漫画 | 继承入口范围，显示章/页数 |
| 内容 | 合成译图（默认）/原图/原图+译文数据包 | 合成模式把遮罩绘入副本；数据包含 manifest、XML 和版本化译文 JSON |
| 格式 | 图片目录/CBZ（默认）/ZIP/PDF | 单页可直接图片；PDF 栅格导出不承诺保留原矢量/文字层 |
| 章节打包 | 每章一个文件（默认）/整漫画合包 | 合包内按章节目录组织；PDF 合包按章/页固定排序 |
| 目标目录 | 系统目录选择器 | 保存可写授权；默认最近使用，首次必选 |
| 图片编码 | PNG/WebP/JPEG；合成默认 PNG | JPEG/WebP 质量默认 90，范围 1–100；原图模式尽可能复制字节 |
| 未翻译页 | 阻止导出（默认）/保留原图/跳过 | 先显示缺失数；不把“无文字已完成”当缺失 |
| 同名冲突 | 自动编号（默认）/跳过/明确覆盖 | 默认不覆盖；覆盖需展示目标 |
| 并发 | 默认 2，范围 1–4 | 与翻译解码共享资源预算，避免内存争抢 |
| 开始导出 | 按钮 | 固定源页、译文版本与渲染设置快照后入队 |

导出顺序使用原章节/页序，不受 UI 筛选排序突然改变。文件名去除非法字符并稳定消歧，防 ZIP 路径穿越、绝对路径和解压炸弹；归档读取设置条目数量、单条解压大小及总临时体积上限，超限可诊断。

队列展示任务状态、已导出页/总页、格式与目标；支持暂停、继续、取消、失败重试、查看输出。图片目录可按页恢复；CBZ/ZIP/PDF 若编码器不能安全续写，则保留进度信息并从当前输出文件重建，不能承诺任意字节断点续传。

先写私有临时产物，完成后发布到目标；SAF 目标不保证原子重命名，需检测提供方能力，复制完成前显示“写入中”，失败留下可辨认临时文件并提供清理。每个成功输出有清单与校验信息，不将半成品标成功。空间不足、授权失效等为可恢复错误。

## 15. 框架与数据设计

### 15.1 建议技术基线

Android 原生 Kotlin、协程/Flow；Compose Material 3 承载主界面；Mihon View 阅读器通过独立适配层接入，先验证分页和条漫，不在首轮同时重写阅读器。Room/SQLite 管理实体和事务；设置用 DataStore；图片加载器只接统一 PageSource；网络使用可取消的客户端适配层。精确依赖版本在搭架时验证并锁定，不因上游不断变化追最新。

初始兼容目标建议 Android 8.0/API 26+，ARM64 真机优先；不是已验证支持。编译/target SDK 以届时工具链和分发要求确定。OCR 原生依赖、模型缺失、PDF 随机访问与阅读器整合是首批技术试验。

### 15.2 模块边界

| 模块 | 职责 | 禁止依赖 |
|---|---|---|
| app / navigation | 导航、依赖装配、主题 | 不直接读写源文件或发翻译请求 |
| core:model | ID、实体、结果类型、错误码 | Android View、网络库 |
| core:storage | SAF、目录、归档、PDF、临时副本 | 业务 UI |
| core:database | 索引、事务、搜索、迁移 | 阅读器 |
| feature:index | Scanner、结构判定、快照对账、元数据 | 翻译模型 |
| feature:library / bookshelf / detail | 列表、收藏、章节操作 | 具体归档解码器 |
| feature:reader | PageSource 适配、进度、遮罩绘制 | 具体 API 供应商 |
| translation:engine | 检测、OCR、prompt、协议、结果校验 | Activity/Fragment/文件夹 UI |
| feature:tasks | 队列、快照、调度、取消恢复、通知 | 具体页面生命周期 |
| feature:export | 输出编排、合成渲染、目标发布 | 直接修改原漫画 |
| feature:settings | 表单与校验、有效配置预览 | 自建第二套设置持久化 |

初期可先用 package 边界避免过多 Gradle 模块；契约稳定后拆 module。核心接口：`ContentTree.listChildren/open`、`StructureScanner.scan(events)`、`ChapterResolver.listPages`、`PageSource.open/render`、`MetadataReader.read`、`TranslationEngine.translate`、`TaskRepository.enqueue/observe/pause/cancel`、`OverlayRenderer.render`、`Exporter.export`。接口返回带身份的结果/错误，不返回 UI 对象。

Task.kind 区分 TRANSLATION/EXPORT，复用等待、准备、执行、暂停、中断、成功、部分失败、失败、取消状态；导出默认不进入 WAITING_NETWORK，远端目标提供方离线时以目标 IO 错误处理。只有 `ExportOutput.publishState=PUBLISHED` 的产物可显示成功；checkpoint 表示完整页或完整输出文件，不表示任意 ZIP/PDF 字节偏移都可续写。全局偏好和 onboarding 标记归 DataStore，漫画级阅读与章节视图偏好归数据库。

身份不使用列表位置、可改标题或单独的绝对路径。重扫 upsert 派生字段，不删除后重建用户关联。重命名能保留文档 ID 则延续身份，否则按重新关联处理。目录模式变化以章节物理身份尽量迁移进度，无法唯一归并时保存旧条目并提示，不猜测。

Manga 唯一约束为 `(anchorNodeId, sourceKind)`，sourceKind 取 IMAGE_DIRECTORY/ARCHIVE_IMPORT；layoutMode 是可修改解释，不放进该唯一键。同一图片来源重复授权不创建重复漫画。**2026-09-25 起两种解释由同一次扫描产出**（§5.1），来源只剩一张表，因此“同一目录在两张表各有一个实体”这一情形不再出现；`sourceKind` 保留为卡片身份的判别位（改它会让已有卡片换 ID、连带丢掉书架与阅读进度），卡片内容改由章节种类表达（`hasArchiveChapters` 徽标）。Chapter 的物理定位键包含 nodeId 和 kind，读者进度按其稳定身份关联。

### 15.4 一致性与任务快照

索引可变状态与用户状态分表，数据库迁移必须可测试。队列包含有效配置快照；编辑全局设置仅影响新提交任务。扫描、翻译、导出并发时均在读取前复核源身份；源改变则当前页停止并标“源已变化”，不可把旧结果写到新源。模型服务不持有 Activity；同一检测器需要的专用线程/互斥由 engine 管理。
