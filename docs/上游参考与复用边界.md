| `app/src/main/java/eu/kanade/presentation/manga/components/MangaChapterListItem.kt` | 章节行交互 | 下载状态换为翻译状态，但保留已读和书签概念 |

| `source-local/src/main/kotlin/tachiyomi/source/local/LocalSource.kt` | 本地漫画/章节、封面、元数据读取 | 本应用自己的单章/递归/根特例/40 分页规则不能直接复用其搜索逻辑 |

| `core-metadata/src/main/java/tachiyomi/core/metadata/comicinfo/ComicInfo.kt` | ComicInfo 模型、扩展字段和映射 | 解耦 SManga；增加 EhViewer 字段和 raw XML 保留 |

Mihon 原生详情操作是阅读、章节/下载等交互；本需求的内容翻译按钮是新增功能，不应写成其既有漫画翻译能力。[详情源码](https://github.com/mihonapp/mihon/blob/f52d890e7f8a3c418ddab41f41d4b577bce0dc06/app/src/main/java/eu/kanade/presentation/manga/MangaScreen.kt)

Mihon 本地源先查漫画顶层 ComicInfo.xml，还能从章节归档查找并复制到顶层；回退过程不是本需求的“固定自然升序第一章”规则，且可能写源目录。LM-Reader 只借鉴读取结构，按开发文档固定首章优先、顶层兜底并只读源。[LocalSource 源码](https://github.com/mihonapp/mihon/blob/f52d890e7f8a3c418ddab41f41d4b577bce0dc06/source-local/src/main/kotlin/tachiyomi/source/local/LocalSource.kt)

两个项目都围绕 ComicInfo，字段集合和扩展不同，不能简单称为“完全不兼容的两种 XML”。兼容策略是容错读取共有及扩展字段、保留原文和来源；既不丢未知字段，也不保证第三方任意畸形 XML 可解析。

## 4. 翻译项目：可提取算法，任务与存储需要适配

本节路径前缀 `app/src/main/java/com/manga/translate/`。

| 文件/符号 | 可借鉴部分 | 必须适配 |
|---|---|---|
| `translation/TranslationPipeline.kt` | 检测→OCR/视觉翻译→结构化结果 | 输入从绝对文件改 PageSource；统一配置快照和结果引用 |
| `translation/TextBubbleTranslationCoordinator.kt` | `items` ID 对应与译文校验 | 保留严格 ID 校验，不按数组位置猜测 |
| `translation/FolderTranslationCoordinator.kt` | 普通/全文/批量页编排 | 去掉以本地文件夹为唯一身份的假设；全文允许禁用自动译名 |
| `detection/PageRegionDetector.kt`、`BubbleDetector.kt` | 气泡/游离文字、长图分块 | 保留模型专用线程与共享实例规则，模型资产单独验证 |
| `ocr/OcrSharedTools.kt`、`PPOcrV6SmallRec.kt`、`KoreanOcr.kt` | OCR 引擎注册、语言路由、识别 | 显式报告不支持语言；不静默按另一语言识别 |
| `network/LlmClient.kt`、`PayloadBuilder.kt`、`ResponseParser.kt` | 协议、prompt 和响应解析 | 全部模式注入字典/有效文风；取消、限流、超时归一 |
| `rendering/BubbleShapePaths.kt`、`BubbleColorSampler.kt`、`BubbleRenderer.kt` | 轮廓填色、取色、排版与导出合成 | 阅读与导出共享布局；测试长图、Unicode、字体溢出 |
| `reader/FloatingTranslationView.kt` | 阅读器内部译文覆盖层 | 适配 Mihon 图像矩阵和页面复用 |
| `floating/FloatingDetectionOverlayView.kt`、`FloatingBallOverlayService.kt` | 系统悬浮翻译 | 属于另一种窗口/截图生命周期；不作为内部阅读器的必要依赖 |
| `storage/TranslationStore.kt`、`OcrStore.kt`、`GlossaryStore.kt` | 页结果、OCR、字典结构 | 应用私有数据、稳定 ID、配置来源、版本与备份 |
| `storage/TranslationTaskPersistence.kt` | 活动任务描述 | 不是冷启动自动续跑队列；本应用另做中断恢复 |
| `settings/SettingsStore.kt` 与领域 Store | 字段/范围/默认值 | 全量映射见翻译配置表，拒绝静默非法值保存 |

关键差异必须落实到代码和测试：

1. 上游全文速译会强制译名处理并关闭 VL；本应用仍让全文模式关闭自动新增译名，已有字典始终参与请求。
2. 上游目标语言与界面语言有关；本应用设置独立的 sourceLanguage/targetLanguage。
3. 上游持久结果校验未覆盖本需求的完整文风/字典版本；本应用保留旧结果，同时区分当前配置是否可复用。
4. VL 请求需要逐条检查字典传入，不能因为普通 OCR 翻译路径支持字典就认为 VL 也支持。
5. 遮罩是区域轮廓填色和译文字体排版，不等于生成式图像修复。
6. 上游冷启动清理活动任务描述，本应用新增持久任务、中断状态、用户继续和页级去重。

证据：[Pipeline](https://github.com/jedzqer/manga-translator-android/blob/809452a4a6b10f520559ad6439e3a85d8ae4c680/app/src/main/java/com/manga/translate/translation/TranslationPipeline.kt)、[文件夹编排](https://github.com/jedzqer/manga-translator-android/blob/809452a4a6b10f520559ad6439e3a85d8ae4c680/app/src/main/java/com/manga/translate/translation/FolderTranslationCoordinator.kt)、[结果 Store](https://github.com/jedzqer/manga-translator-android/blob/809452a4a6b10f520559ad6439e3a85d8ae4c680/app/src/main/java/com/manga/translate/storage/TranslationStore.kt)、[Prompt 解析](https://github.com/jedzqer/manga-translator-android/blob/809452a4a6b10f520559ad6439e3a85d8ae4c680/app/src/main/java/com/manga/translate/platform/PromptAssetResolver.kt)

### 4.1 模型资产门槛

本次克隆中根 `assets` 只有 prompts，`app/src/main/assets` 不存在。源码引用至少涉及：

- `models/detection/mixed-dual-s-e5_float16.tflite`：气泡/文字检测。
- `models/detection/PP-OCRv6_det_mobile_infer.onnx`：行检测。
- `models/ocr/PP-OCRv6_small_rec.onnx` 及对应字符字典：识别。
- `models/ocr/korean_PP-OCRv5_mobile_rec.onnx` 及对应字符字典：韩文识别。

因此“拉取源码即可完整离线翻译”没有成立。P0 应登记每项真实下载来源、文件名、SHA-256、输入输出规格、体积及许可证；有资产并能加载后再做质量与速度验证。不能只按 README 的历史模型列表硬编码。[README 模型说明](https://github.com/jedzqer/manga-translator-android/blob/809452a4a6b10f520559ad6439e3a85d8ae4c680/README.md)

## 6. DeepSeek 调度与主审复核

使用 `deepseek-coding-delegate` 的本地 runner 分三个边界明确的任务调查：

| 任务 | 草稿 | 执行结果 |
|---|---|---|
| 阅读器/图库/ComicInfo 源码 | `.research/reports/reader-audit.md` | runner 返回 0 |
| 翻译流水线/设置字段 | `.research/reports/translation-audit.md` | runner 返回 0 |
| 逐屏控件/验收用例 | `.research/reports/ui-requirements-draft.md` | 已产出草稿，但 runner 返回 1；不能视为完整成功 |
| 四文档交叉审阅 | `.research/reports/final-doc-review.md` | runner 返回 0，列出 12 项修订建议，主审逐项处理 |

主审独立检查了三个固定提交、源码工作区状态、ComicInfo 两侧模型、Mihon LocalSource、翻译设置门面/部分 Store 与 UI、模式契约、模型目录、PageLoader 及相关枚举，并重写正式需求规格。剔除了草稿中“两个 XML 完全不兼容”“PageLoader 无依赖”“UI 草稿中的所有建议均已确认”等不可靠归纳。

没有对 DeepSeek 的全部上游细节逐行证明；草稿保留调查线索和不确定项，正式文档只采用需要的事实与明确标注的设计基线。没有 Android 自动测试/构建通过的结论，也不宣称节省了多少 token。

最终审阅后补充：漫画跨来源唯一键、首启标记、阅读/筛选偏好表、导出产物表、稳定会话分页、主源顺序、草稿保存、卷层级样例、VL 结构化字典响应、漫画级搜索投影与索引。并机械提取 SettingsStore 的 79 个字符串 `KEY_*` 常量，确认全部有字段或组合映射；这项覆盖核对不等同运行验证。
