# 阅读器位置重构：实施计划

基线：`3397630`（含加载链修复、每帧重建环修复、搜索与书架改动）。
目标：消除"快速翻页时位置偏移"这一类 bug（偏 3 / 偏 4 / 跳回上一章首页 / 过渡页重复 / 1 页章被漏）。
参照：Mihon 的实现（`.research/mihon/.../reader/viewer/pager/PagerViewer.kt` 等）。

---

## 0. 一句话设计与"不做什么"

**把"读者在哪"从"`items` 的下标"改成"项身份（key）"，并按 Mihon 的变更协议重建同步机制。**

明确**不做**的事（都是上一轮讨论里被否掉的）：

| 不做 | 原因 |
|---|---|
| 改成"只增不减的大表" | Mihon 用的是滚动窗口，证明滚动窗口本身没问题；只增不减会把 `items` 也变成无界，且异步加载仍会插到当前项之前 |
| 改成环形队列 | 视觉列表必须线性有序，环形会多出一层"环位置 → 线性下标"的翻译，正是出错的那层 |
| 改 `loaded` 的淘汰策略（本计划内） | 与位置无关，放到第 3 阶段；现在 `loaded` 无界但只是元数据 |
| 改过渡项的默认开关 | 属于产品决策；本计划只保证"不因重排而抽走脚下的过渡项" |

---

## 1. 根因回顾（一句话）

状态机按下标记位置，而分页器自己存了一份数字位置；`items` 一变（窗口前滚会丢掉整整一章），
两份数字就对不上。**而我们的落页收集器还用 `items.size` 当 `LaunchedEffect` 的 key**——
列表一变它重启并**立刻重发一次当前值**，恰好把"重排之前的旧数字"当成读者位置上报。
偏移量因此恒等于"被丢掉那一章在列表里占的格子数"= 页数 + 1（用户实测：2 页 → 偏 3，3 页 → 偏 4）。

## 2. 设计

### 2.1 位置：唯一真相是身份

```
positionKey : String     // 真相：pageId 或 "transition:from->to"
items       : List<ReaderItem>
currentPageIndex : Int   // 派生量：items 里 positionKey 的下标，items 一变就重算
```

规则：
- **读者移动**（`move` / `settleAt` / 滑杆 / `openAt`）：先写 `positionKey`（由目标项得到），再写派生下标。
- **列表重排**（`writeItems`）：`currentPageIndex = items.indexOfKey(positionKey)`。
  这是**唯一**的定位方式，取代现在的 `reanchorIndex(旧列表, 旧下标, 新列表)`。
- **身份消失**（理论上不该发生：窗口永远含当前章及其相邻章）：
  退化为"同一章最接近的第 0 页"，并把 `positionKey` 改写为新值 —— 同时**记一条日志**，
  因为这个分支意味着窗口策略被破坏。

### 2.2 变更协议：三道闸（照搬 Mihon）

| 闸 | Mihon | 我们对应做法 |
|---|---|---|
| ① 只在空闲时换数据 | `setChapters` 非 idle 就排队到 `awaitingIdleViewerChapters` | `ReaderViewModel` 记 `scrolling`；滚动中把算好的窗口挂到 `pendingWindow`，落定后应用 |
| ② 换数据不产生"页变了"事件 | `removeOnPageChangeListener` → 换 → `addOnPageChangeListener` → 手动 `onPageChange` | 分页器侧 `syncing` 标志：重排期间**不接收** `settledPage` 回报，归位完成后再开 |
| ③ 换完按身份重新定位 | `moveToPage` = `items.indexOf(page)`；`refreshAdapter` = `setCurrentItem(currentItem, false)` | 同步 effect 的 key 从"项身份"改成 `(positionKey, currentPageIndex, items.size)`，**滚动中也强制** `scrollToPage(target)`，且不再因 `isScrollInProgress` 一次跳过就永远不补 |

## 3. 分步实施

每一步都是一个**独立可编译、可回滚**的提交。

### 第 1 步：位置真相换成身份（纯状态层）

**改动**
- `ReaderChapters.kt`：新增 `internal fun List<ReaderItem>.indexOfKey(key: String): Int`；
  保留 `reanchorIndex` 但降级为"身份消失时的兜底"（并在注释里写明它不再是主路径）。
- `ReaderViewModel.kt`：
  - `ReaderUiState` 增 `positionKey: String`；`currentPageIndex` 注释改为"派生量"。
  - 新增 `private fun positionOf(items, key): Int`。
  - `writeItems`：用 `indexOfKey` 定位；找不到才落回 `reanchorIndex` + 日志。
  - `settleAt` / `move` / `jumpToPage` / `jumpToAdjacentChapter` / `openAt`：
    写下标的同时写 `positionKey`。
- `ReaderChaptersTest.kt`：新增
  - "窗口前滚后，同一项的身份仍能定位到新下标"（对当前章与过渡项各一次）；
  - "身份不在列表里时退回兜底且不改坏位置"。

**不变量**
1. 任何时刻 `items.getOrNull(currentPageIndex)?.key == positionKey`（除身份消失的兜底瞬间）。
2. `positionKey` 只在"读者移动"时改变。

**验证**：`:app:testDebugUnitTest`（含既有 32 条用例，必须全绿）。
**回滚点**：`git revert` 本步提交即可，行为与基线一致（因为同步层还没改）。

### 第 2 步：变更协议（分页器 + 条漫 + ViewModel）

**改动**
- `PagerReader.kt`
  - 新增入参 `positionKey: String`（来自 state）。
  - **删掉** `LaunchedEffect(pagerState, items.size)` 里用 `items.size` 作 key 的写法 → 改成
    `LaunchedEffect(pagerState)` 只在**读者动作**时收 `settledPage`；重排期间由 `syncing` 屏蔽。
  - 归位 effect：key 换成 `(positionKey, currentIndex, items.size)`；滚动中先等落定再
    `scrollToPage(target)`（并设 `suppressSettleFrom`）。
  - 新增 `LaunchedEffect(pagerState) { snapshotFlow { isScrollInProgress }.collect(onScrollingChanged) }`。
- `StripReader.kt`：同样的三处（它现在也是按下标回报 + `items.size` 作 key）。
- `ReaderViewModel.kt`：
  - `onScrollingChanged(value: Boolean)` + `pendingWindow`；`writeItems` 在滚动中且窗口确实变了时挂起。
  - `onCleared` / 阅读器销毁时清 `scrolling`（避免永久挂起）。
- `ReaderScreen.kt`：把 `positionKey` 传给两种渲染器；`DisposableEffect` 里报告"非滚动"。

**不变量**
3. `items` 只在 `scrolling == false` 时被替换（`sameWindow` 的等价写不在此限）。
4. 重排之后，状态机收到的第一个落页回报要么被屏蔽，要么其项身份 == `positionKey`。

**验证（关键一步）**
- 单测：新增 `positionKey` 在窗口前滚后不变的用例（纯函数层）。
- 模拟器（夹具：10 章 × 3 页，与用户场景一致）：
  - **必须用 swipe 驱动**：`input tap` 间隔 <300ms 会被引擎的 `GestureDetector` 判成双击，
    一次翻页都不会发生（这一条已经踩过）。
  - 用例：进第 N 章第 1 页 → 向前滑 4 次（3 页 + 1 过渡）→ **应停在第 N+1 章第 1 页**；
    连续走到第 5 章，每一步核对顶栏章节名与页码指示。
  - 反向：从第 N 章第 1 页往回滑 4 次 → 应停在第 N-1 章第 3 页（不是"跳回更早的章"）。
  - 快滑：0.4s 间隔连滑 8 次，确认停点与手数一致。
- 真机：由用户确认（我负责装包 + 给测试步骤）。

### 第 3 步（本计划外，先记录）：结构调整

- 窗口形状稳定化：把预算用在**加载**上，不要用在**显示窗口**上（现在边界章页数一量到窗口就变大小）。
- 过渡项照搬 `forceTransition`：读者正站在过渡项上时不抽走。
- `loaded` 加上限（当前章 ±20 章，约 180 KB）。
- 竖向分页的 `beyondViewportPageCount = 0` 与横向（2）不一致。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 屏蔽回声时把用户的真实翻页也吃掉 | 屏蔽窗口只在"重排后归位"期间开启，且第 1 步保证重排不发生；若发生，落定后 `scrollToPage` 会立即结束屏蔽 |
| 滚动中挂起的窗口长期不应用（阅读器被销毁/滑动状态没上报） | `DisposableEffect` 与 `onCleared` 都强制清 `scrolling` 并冲刷 `pendingWindow` |
| `scrollToPage` 打断用户的 fling | 第 ① 道闸保证重排不会发生在滚动中；真发生时以"位置正确"优先（Mihon 同样取舍） |
| 身份消失分支被静默走到 | 该分支打日志；模拟器验证时检查日志里这条出现次数为 0 |
| 条漫模式回归 | 条漫单独跑一轮同样的用例（进度恢复 + 前后滚动） |

## 6. 进度与验证记录

### 第 1 步 ✅ 已完成（`6a898e4`）

纯状态层：`positionKey` 成为位置真相、`currentPageIndex` 降级为派生量；
`writeItems` 改用 `indexOfKey`（身份定位），只在身份找不到时才退回 `reanchorIndex` 并记日志；
`settleAt` 的"没动"判据改为"下标与身份都相同"。
新增 3 条单测（含"按身份定位不会换项、按下标会"这条核心断言），35 条全绿。

### 第 2 步 ✅ 已完成（`18e4d3b`）

变更协议三道闸（照搬 Mihon）：
① 滚动中不替换项列表（`scrolling` + `pendingWindow` + 渲染器上报）；
② 落页收集器的 key 从 `(pagerState, items.size)` 改为只剩 `pagerState`，并加 `syncing` 门；
③ 归位 effect 的 key 换成 `(positionKey, currentIndex, items.size)`，等落定后强制 `scrollToPage`。

顺带修掉第 1 步的一个误报：`openAt` 是"先建窗口、后落页"，此时 `positionKey` 是空串，
不该被当成"身份找不到"。空串现在走单独的、不告警的分支。

#### 模拟器验证（夹具 10 章 × 3 页，与用户场景一致）

操作要点（**下次验证必须照做**）：
- **滑动方向是"手指从左往右"**（右到左模式的 `reverseLayout`）；反向滑不翻页。
- **点击**：`input tap` 间隔 ≥1.0s 才是"一次一格"；<300ms 会被引擎的
  `GestureDetector` 判成双击（引擎用它做缩放），一页都不会翻。
- **滑动**（`input swipe 150 450 1500 450 600`）是 fling，一次可能跨 2 格，不能用来数格子。

结果：

| 检查项 | 结果 |
|---|---|
| 触发前端丢弃（第 4 章第 1 页，`idx 12 -> 8`，平移 4） | 仍停在 **Chapter 4 · 1/3** ✓ |
| 前进 12 格 | **Chapter 7 · 1/3**（正好 3 章） ✓ |
| 后退 12 格 | **Chapter 4 · 1/3**，且与进入第 4 章时的截图**逐字节相同**（往返精确） ✓ |
| "身份找不到"告警 | 全过程 **0 次** ✓ |
| 1 页的章（把第 4 章临时改成 1 页） | 点 12 次落在 **Chapter 4 · 1/1**，未被跳过；再过一格过渡项到 **Chapter 5 · 1/3** ✓ |
| 回归 | 5 模块单测 + 构建 + lint 全绿 ✓ |

造 1 页夹具的办法：`adb shell rm -f "<章节目录>/002.jpg" "<章节目录>/003.jpg"`（用完再把 001 复制回去）。

#### 验证时观察到、留给第 3 步的问题

每次跨章会产生**两次**项列表重排：

```
window 5->4 items 19->15 idx 12->8   wind=[350e, 0a8e, 09b4, cb19]       ← 先丢前端一章
window 4->5 items 15->19 idx 8->8    wind=[350e, 0a8e, 09b4, cb19, 876d] ← 再追加后端一章
```

两次相隔约 4ms，来自两个不同的重建入口（`settleAt` 与 `loadOne` 完成）。
位置没有错（两次都按身份解到位），但**白重排一次**——这正是第 3 步"窗口形状稳定化"要治的。

### 第 2 步补丁 ✅ 已完成（`5a03488`）

真机反馈：**高速连续滑动**时位置会回跳（从第 6 章滑到第 7 章，过渡页先显示第 7 章、
随后变成第 5 章；继续快滑重复成 567567，停下才恢复）。两处根因都在第 2 步的协议里：

1. **挂起的是"陈旧的窗口"**：`pendingWindow` 保存的是按"当时那一章"算好的窗口，
   快滑时读者已前进好几章，落定后照原样应用 → 窗口里没有当前位置的项 → 身份找不到 →
   退回下标重锚 → 跳到几章之前。**改为只记 `rebuildPending`，落定后重新规划。**
2. **归位 effect 盯了 `currentIndex`**：读者自己翻页也算"位置变了"，于是把已经滑到前面的
   分页器拽回状态记得的旧位置；而且它会先等"滚动停止"，把这次拽回推迟到读者下一次
   滑动的中途。**改为由显式信号 `positionSyncToken` 驱动**，只在"状态机主动移动"或
   "项列表被替换"时自增。

顺带在分页器里加了一条不变量自检：归位目标的下标必须解出 `positionKey` 本身，
否则 W 级告警——这条本来就能抓住第 1 类问题。

验证：高速连滑 16 次（0.35s 间隔）下标单调前进、无重复、告警 0 次、结束位置与日志一致；
点击前进 8 次落在 `Chapter 3 · 1/3`、后退 8 次截图与起点逐字节相同。

## 8. 后续调整：两项参数挪到「设置 → 阅读器」

「预载页数」与「缓存章节数」**只在打开阅读器之前生效**（分别决定预取多少字节、
在内存里保留多少章的页清单，都在 `ReaderViewModel.init` 之后按当时读到的设置生效），
放在阅读中的设置面板里会让人以为"拉一下立刻变快"。因此：

- 新增「设置 → 阅读器」页（`ui/settings/reader/ReaderSettingsScreen.kt`），
  `SettingsHomeScreen` 的「阅读器」项由"未实现"改为可用，路由 `settings/reader`。
- 阅读中的设置面板「章节」段只留「显示章节过渡页」，并加一句指路文案。
- 滑杆控件抽到 `ui/common/LabeledSlider.kt`（两处共用，避免手感不一致）。
- 范围调整：**预载页数 4–20**（下限 4 是因为保留的已解码页数按 `preloadPages / 4` 算，
  4 正好对应"两侧各留一页"，再小会退化成 0、落页时露出未解码的页）；
  **缓存章节数 4–15**。
