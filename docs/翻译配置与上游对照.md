# 翻译配置与上游对照

版本 0.1，2026-09-25。配套 [开发文档](./开发文档.md)，以 manga-translator-android 提交 `809452a4a6b10f520559ad6439e3a85d8ae4c680` 为调查基线。

本表是实现清单，不表示这些设置已经接线。上游字段与默认值来自 DeepSeek 静态调查、主审对 SettingsStore/Store/枚举/部分 UI 的复核；上游实际推理效果尚未验证。LM 默认值是新应用的设计决定，不伪装成上游默认。

## 1. 设置组织、控件和保存

- 全局配置分组页；每漫画可选择跟随全局或覆盖。有效值、来源和影响范围须可见。
- 所有编辑表单有取消/保存；保存校验整个分组，失败保留输入且不修改旧值。离开有未保存修改时提供保存/放弃/继续编辑。
- `Boolean` 用开关，枚举用单选/下拉，有界数值用数字框+单位，可视外观数值可同时提供滑杆；文本用多行框；密钥用密码框和显隐按钮。
- 按协议/模式隐藏或禁用不适用字段，并说明原因；被禁用字段保留已保存值，不能静默重置。
- 导入设置先预览版本、冲突与非法字段，事务应用；模型缺失或网络不可用不阻止保存草稿，但阻止提交不可执行的翻译任务。
- 每个新增/删除的设置必须更新本表、序列化 schema、迁移和有效配置快照；上游新增字段不自动混入本版。

表中“保留”指保留能力和已列的值域；对于上游宽松、静默截断或副作用式保存，本应用统一采用显式校验，不照抄错误行为。

## 4. 翻译方式、语言与文风

源码入口：`library/LibraryPreferencesGateway.kt`、`library/LibraryFragment.kt`、`settings/AppSettingsStore.kt`、`platform/PromptAssetResolver.kt`。

| ID / 上游字段 | 控件 | 上游默认/行为 | LM 默认与变化 |
|---|---|---|---|
| TR01 `full_translate_enabled_<path>` | 全文速译开关 | 开 | 关；全局默认+漫画覆盖，身份用 mangaId |
| TR02 `glossary_processing_enabled_<path>` | 译名处理开关 | 开；全文下强制开 | 开；全文下仍允许关闭自动新增；所有请求继续应用既有字典 |
| TR03 `vl_direct_translate_enabled_<path>` | VL 整气泡开关 | 关；全文下强制关 | 关；与全文互斥，切换时说明；主翻译模型须支持视觉 |
| TR04 `translation_language_<path>` | 源语言单选 | 日语；历史枚举带 `_TO_ZH` 名称 | **原文语言：没有全局默认**（用户口径：每部作品必须手动选）；日/英/韩/简中/繁中/中英混合/法/西/葡/德/意/俄 + 自定义 |
| TR05 上游依赖 `app_language` 的目标 | 目标语言单选，LM 拆出 | 按界面语言选 prompt 目标 | **默认就是应用现在使用的语言**（用户口径）；漫画可逐部覆盖；简中/繁中/英语/日语/韩语/俄语/巴西葡语 + 自定义 |
| TR06 `translation_style` | 多行文本 | 内置日漫文风；空时回退 | 内置“忠实原意，译文自然流畅，保持人物语气、称谓和前后文一致，不添加解释。” |
| TR07 漫画文风来源 | 文本+恢复默认/跟随类别/应用 | 上游无三层继承 | CATEGORY 默认；GLOBAL/CUSTOM 通过专用弹窗改变 |
| TR08 分类文风 | 分类编辑内的文本+跟随默认开关 | 上游无本需求语义 | 跟随全局；独立内容有 revision |
| TR09 漫画译名字典 | 原词/译名键值对、新增、删除、保存 | 按文件夹维护 JSON | 按 mangaId 维护（**与语言无关**，用户口径），跨章节共享，人工值不被自动覆盖 |

语言列表来自上游已定义的来源与 prompt 家族，不说明所有语言在本地 OCR 上都有相同准确率。源=目标可以保存，用于混排或文风处理，但显示同语言提示；不自动改设置。

全文速译：先按受限页块 OCR、可选译名预提取，再批量翻译文本。标准/VL/全文不能因为关闭译名处理而跳过现有字典。所有模式明确附带当前目标语言、文风、字典；模型响应 v1、VL 的 source_text 与 glossary_used 校验采用主文档 10.2 的统一契约，不能以原文纯字符串输出替代开启译名处理时的结构化结果。

## 5. LLM 采样、思考与自定义参数

源码入口：[LlmParameterStore](https://github.com/jedzqer/manga-translator-android/blob/809452a4a6b10f520559ad6439e3a85d8ae4c680/app/src/main/java/com/manga/translate/settings/LlmParameterStore.kt)、`model/ThinkingLength.kt`、`settings/ui/dialogs/LlmParamsDialog.kt`、`network/PayloadBuilder.kt`。

LM 的可选字段都有“由服务商默认”选项（不发送该字段）。无法解析的输入阻止保存；不能像某些上游路径一样悄悄变成 null。范围为本应用校验基线，模型能力描述可进一步收窄。

| ID / 上游键 | 控件/选项 | 上游默认 | LM 默认与约束 |
|---|---|---|---|
| LLM01 `llm_temperature` | 可空小数 | 0.8 | 0.8，0–2；供应商不支持时不发送 |
| LLM02 `llm_top_p` | 可空小数 | 1.0 | 1.0，0–1 |
| LLM03 `llm_top_k` | 可空整数 | null | 不发送；设置时 ≥1 |
| LLM04 `llm_max_output_tokens` | 可空整数 | null | 不发送；设置时 ≥1 且不能超过模型声明上限 |
| LLM05 `llm_frequency_penalty` | 可空小数 | null | 不发送；−2 至 2，按供应商能力校验 |
| LLM06 `llm_presence_penalty` | 可空小数 | null | 同上 |
| LLM07 `llm_enable_thinking` | 开关 | 关 | 关；协议不支持此字段时不要无条件发送 false |
| LLM08 `llm_thinking_length` | 单选 auto/low/medium/high/xhigh | medium | medium；思考关时禁用；不支持的级别不可选 |
| LLM09 `llm_thinking_budget` | 旧键迁移 | 旧值迁移后删除 | 仅导入兼容，不再另建重复控件 |
| LLM10 清除采样参数 | 按钮 | 上游清空六采样项 | 当前草稿六采样项改为不发送，思考开关与等级不变；保存后生效 |
| LLM11 恢复默认 | 按钮，LM 明确 | — | 草稿回到表中 LM 默认值，不发送请求 |
| LLM12 `custom_request_parameters` | 键/类型/值/启用/删除表，`+` | 空数组 | 增加显式 String/Number/Boolean/Object/Array/Null 类型，避免原文自动猜型 |

思考等级到数值预算的映射不能作为通用模型事实。上游 `ThinkingLength` 的历史映射为：OpenAI 系 auto/low/medium/high/xhigh → 4096/1024/4096/8192/16384；Gemini → −1/1024/8192/24576/32768，且 OpenAI UI 隐藏 auto。LM 将映射放进供应商能力适配器，优先采用服务端支持的语义字段，不凭这个表保证某个未来模型可用。

自定义参数键不能为空或重复，不能覆盖 `model/messages/input/instructions/contents/systemInstruction/generationConfig` 以及已由专用字段生成的键；错误就地显示冲突键。作用域默认主翻译请求，不自动污染 OCR 请求。允许编辑、启用/禁用、删除、保存；对象/数组必须是合法 JSON。Prompt 中漫画文本和字典作为待处理数据，不允许改变工具或协议。

## 7. 悬浮窗完整对照与作用域

| FL25 拖动/折叠/位置复位（新增明确） | 手势+菜单 | — | 核心内部控制；横竖屏各保存位置 |

上游手势候选是 start_translate/open_menu/clear_screen/none/swipe_translate。本应用内部候选为翻译当前页/打开菜单/切换原图遮罩/隐藏控制条/无；swipe_translate 属于系统扩展。手势动作可从单独菜单配置，不能让删除源文件或删除译文成为默认手势。

系统扩展如后续纳入，必须另做屏幕捕获授权、悬浮窗口生命周期、截图隐私、背景请求与屏幕变化语义的规格和验收；不能将这个扩展与本地图片遮罩混成同一“必需权限”。

## 9. 设置变化如何影响已有数据

| 修改 | 新任务 | 已提交任务 | 已有结果 |
|---|---|---|---|
| URL/Key/供应商组 | 用新配置 | 用旧快照；失效 Key 可暂停后“更新连接参数并继续”，必须记录这一动作 | 保留，可阅读；不删除结果 |
| 源/目标语言、文风、模式 | 用新值 | 不变 | 保留，标当前配置待更新 |
| 手工字典修改 | 新任务用新版本 | 正在执行请求不变；提示版本变化 | 不静默批量重译 |
| 同任务自动新增译名 | 后续批次可使用 | 串行合并并记录每批快照 | 已完成页保留当时上下文，不循环作废全任务 |
| 字体、透明度、取色、横竖排 | 渲染用新设置 | 导出用提交时快照 | 重绘即可，不请求模型 |
| OCR/检测模型或参数 | 新处理用新版本 | 不变 | OCR 可重算，已有译文保留并提示相关版本变化 |
| 图源内容实际变化 | 需新内容哈希 | 当前页终止，源变化错误 | 旧结果保留历史，但不能覆盖新图显示 |

## 10. 覆盖核对与实现门槛

本轮已核对的范围是本表列出的 SettingsStore 门面及对应 Store、LibraryPreferencesGateway、悬浮窗四边检测区域、更新偏好、导出参数，以及备份/字体/日志/气泡编辑入口。对固定提交 SettingsStore 中字符串字面量定义的 79 个 `KEY_*` 常量进行了机械提取：79/79 均在本表有直接字段或明确的组合/主题角色映射；逐键结果保存在 `.research/reports/settings-key-coverage.json`。这证明已列主门面键的文档映射，不证明每个默认值和运行依赖都已真机验证，也不声称自动发现了全仓所有动态偏好键。

LibraryPreferencesGateway 的目录前缀键、主设置以外的左右边距/更新/导出键已单独查阅并映射。未列作用户设置的内容包括内部页面缓存、临时任务状态、旧迁移标记、源应用版本号及缺失模型二进制内的参数；旧迁移键与内部派生状态仍注明去向。未发现必须新增到本表的主门面键；非主门面的动态键完整性、所有 UI 入口的实际接线和各模型能力仍是 P0/P3 的验证项。

框架实现时维护可机读 `SettingDefinition(id,type,default,scope,validator,dependencies,snapshotPolicy)`；双向验证“固定提交的设置来源→本表映射或排除原因”及“本表可编辑项→UI 或明确扩展状态、持久化和有效值解析”，避免只检查表内项而发现不了上游漏项。将本表 ID 关联到 UI 测试，至少覆盖：取消不保存、非法输入不保存、恢复默认只改草稿、模式互斥、目标语言不随 UI 语言变化、配置快照稳定、字典六组合请求。

本轮没有验证所有供应商模型支持所有参数；“可填字段”与“该模型支持”分开。能力测试失败应显示具体字段并允许用户改为不发送，不擅自吞掉参数后宣称使用了该设置。
