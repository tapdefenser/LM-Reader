## 三、五个根因（都已修，附机理，避免重复调查）

### 1. 阅读器"最多只能读 4 章"

`rebuild()` 只重排窗口、不请求加载；而 `loadOne` 的守卫是 `loadJobs`，条目**从不移除**，
于是它退化成"曾经请求过"的集合。进第 1 章请求 2/3/4，三章完成后 `chaptersToLoad` 仍只返回
2/3/4、全部命中守卫 → **加载链断了**，窗口永远停在 `[1,2,3,4]`。

修法：`rebuild()` 里补 `loadNeighbors()`（规划与加载必须一起发生）；守卫拆成
`loadJobs`=正在加载 / `loaded`=已有结论（含失败）；`finally` 移除条目；
`retryFailedChapters` 先摘掉失败结论再重试。

### 2. 每帧重建环（native 300MB、SIGABRT）

`buildWindow` 有界化后，**窗口内容依赖当前章**，而当前章是"落页回报的下标 → 项"反推的
→ 正反馈环：章翻转 → 窗口重算 → 表长 11↔15 变化 → 分页器（右到左 `reverseLayout`）
的"偏移↔下标"映射抖一格 → 下一次落页指到相邻的另一章 → 再翻转。
实测每秒重建 80+ 个引擎视图、同一页 `setImage` 111 次。

修法三处：`chapterEnteredBy(item)`（**过渡项不算换章**，只有落到页才算进入那一章）；
`settleAt` 只在换章时才重建；`writeItems` 在窗口的章 id 序列没变时**连 `items` 实例都不换**。

> 我一度只用 `dumpsys meminfo` 对照就断言"这是引擎的固有代价、不是回归"——**错的**。
> 用户的质问（"按预算内存里只该有约 5 页，怎么会 OOM"）是对的。教训：
> **内存总量不能用来归因，必须同时数事件次数**（见 `交接-新对话接手.md` 教训第 8 条）。

### 3. 快翻时位置偏 3 / 偏 4 / 跳回上一章 / 过渡页重复 / 1 页章被漏

四项同源：落页收集器的 `LaunchedEffect` **把 `items.size` 也当成了 key**，
列表一变 effect 就重启，而 `snapshotFlow` 会立刻重发当前值——那一刻分页器记的往往还是
**重排之前**的数字，下标又恰好平移了一整章 → 状态机把"另一个项的下标"当成读者位置。
偏移量恒等于"被丢掉那一章在列表里占的格子数"= **页数 + 1 个过渡页**
（用户实测：前一章 2 页 → 偏 3；3 页 → 偏 4，完全吻合）。

修法：位置改**项身份**（`6a898e4`）+ 变更协议（`18e4d3b`）。

### 4. 快滑 567567 循环（第 2 步引入的回归）

两处：① `pendingWindow` 存的是**按当时那一章算好的窗口**，快滑时读者已前进几章，
落定后照原样应用 → 窗口里没有当前位置的项 → 身份找不到 → 退回下标重锚 → 位置跳到几章之前；
② 归位 effect 盯 `currentIndex`，把"读者自己翻页"也当成"位置变了"，且会先等滚动停止
→ 把已滑到前面的分页器**拽回**（且推迟到下一次滑动中途）。

修法：只记 `rebuildPending`（落定后**重新规划**）；归位改由显式信号 `positionSyncToken`
驱动（只在"状态机主动移动"或"项列表被替换"时自增）。

### 5. 每次跨章白重排两次

窗口按**页数预算**切段，而预算用已知页数、页数要加载完才知道 → "边界章刚量到页数"当场
改变窗口大小（实测 `items 19->15` 与 `15->19` 相隔 4ms）。
修法（第 3 步）：**窗口 = 已缓存的章**，预算只决定"加载哪几章"与"预取哪些字节"。

## 四、当前阅读器架构（改代码前必读）

### 位置

```
positionKey : String     // 真相：pageId 或 "transition:from->to"
items       : List<ReaderItem>   // 窗口里已缓存章的页 + 章之间的过渡项（线性）
currentPageIndex : Int   // 派生量：items 里 positionKey 的下标
```

不变量：`items.getOrNull(currentPageIndex)?.key == positionKey`。
定位一律用 `ReaderItem` 列表的 `indexOfKey()`；`reanchorIndex()` **只是兜底**
（身份找不到时），走到那条分支会打 W 级日志（意味着窗口策略被破坏）。

### 窗口与加载（二者已解耦）

- **显示窗口 = 已缓存的章**（`buildWindow(chapterList, currentChapterId, existing)`）。
  与当前章无关，因此正常前进时**只追加**，下标不平移。
- **加载**由 `planFor` 的格数预算（预载页数 → 往后 total/2、往前 total-total/2）
  + 单侧上限 3 章 + **边界章**规则决定，`chaptersToLoad` → `loadOne`。
- **淘汰**（`evictLoadedChapters`）按"离当前章最远优先"，三条红线：
  当前章 / 当前章 ±1（过渡项靠它生成）/ 正在加载的章 **永不清除**。
  实际保留 = `1 + 2 * max(设置值, MAX_PRELOAD_CHAPTERS_PER_SIDE + 1)`。

### 变更协议（照搬 Mihon，读 `PagerViewer.kt`）

1. **滚动中不替换项列表**：`scrolling` + `rebuildPending`，落定后 `rebuild()` 重新规划。
2. **换数据本身不产生"页变了"事件**：落页收集器 `LaunchedEffect` 的 key **只有** `pagerState`。
3. **归位按身份、只由信号驱动**：`ReaderUiState.positionSyncToken` 只在
   "状态机主动移动读者"（`moveTo` / `openAt`，见 `requestPositionSync`）或
   "项列表被替换"时自增；渲染器 `LaunchedEffect(positionSyncToken)` 把它挪到位。
   另有不变量自检：解出的下标必须对应 `positionKey`，否则 W 级告警。

### 其它关键点

- `chapterEnteredBy(item)`：**过渡项不算换章**。
- `EnginePageView`：一页一个引擎视图；同一页只 `setImage` 一次（每次都是整图解码）。
- 保留的已解码页 = `preloadPages / 4`（上限 2）→ 横向与竖向**同一值**（竖向曾写死 0）。
- 进度只存页码，`intraPageRatio` 恒 0；落在过渡项上**不写进度**。

## 五、设置入口（最近的调整）

- **「设置 → 阅读器」**（主菜单 → 设置，`SettingsHomeScreen` 第 3 项，路由 `settings/reader`）：
  「预载页数」**4–20**、「缓存章节数（前后各）」**4–15**（默认 10）。
  **只在下次打开阅读器时生效**——这也是它们从阅读中面板挪出来的原因。
- 阅读中的设置面板（齿轮）保留方向/连续模式/缩放/裁白边/音量键/亮度/点按区域/
  显示章节过渡页（这些改了立刻生效）。
- 图库搜索**限定在已应用的图源筛选内**（`searchInSources`，下推到 SQL）。
- 书架刷新键语义 = "更新当前筛选下所有收藏的**章节**"（`shelfMangaIds` + `MangaChapterSyncer`），
  不是刷新列表；列表读取失败的「重试」走 `reload()`。

### 输入的三条铁律（都踩过）

1. **`input tap` 间隔必须 ≥1.0s**。<300ms 会被引擎的 `GestureDetector` 判成双击
   （引擎用它做缩放），**一页都不会翻**。想精确数格子就用 tap + 1.0s。
2. **右到左模式下，手指"从左往右"滑才向前翻页**（`reverseLayout`）。
3. **`input swipe 150 450 1500 450 600` 是 fling，一次可能跨 2 格**，不能用来数格子。

  判断"有没有环"要看**事件计数**（此处临时加 `Log.d` 计数后撤掉），不能只看总量。

## 七、已被否掉的方案（**不要回去**）

| 方案 | 为什么否掉 |
|---|---|
| `promoteChapter` / "跨章事件" / `resolveLanding` | 把跨章当事件 → 跳页、卡住、"有时进下一章有时被送回上一章" |
| 按下标表达位置（含 `reanchorIndex` 当主路径） | 窗口/淘汰一旦重编号就静默错页；现在只作兜底 |
| 保存"算好的窗口"延后应用（`pendingWindow`） | 快滑时它是陈旧的 → 位置跳到几章之前（567567） |
| 归位 effect 盯 `currentIndex`/`items.size` | 反向把读者拽回；且会推迟到下一次滑动中途执行 |
| `nearWindowEdge` 门控重建 | 窗口不再按预算切段后它没有意义，已删除 |
| `cameFromScrollIntoView` | 从未被置 true 的死代码，已删 |
| 只增大表（不淘汰）/ 环形队列 | Mihon 用的是滚动窗口；环形会多一层"环位置→线性下标"的翻译。改用"窗口=缓存 + 按设置淘汰" |
| Mihon 的 `forceTransition` | 不需要：它的过渡项默认是加载占位所以会被抽走；我们常开 + 淘汰红线保证当前章 ±1 永在 |
| 全区域覆盖的滚动条触摸层 | Compose 重叠兄弟节点**不是**"不消费就穿透"，会吃掉整个列表的点击 |
